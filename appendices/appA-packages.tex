  \api{init\_chat\_model}. \textbf{6 submodules.} Depends on \pkg{langgraph}. \\[3pt]
\pkg{langchain-classic} & The retired surface. \textbf{43 submodules.}
  Maintenance mode; a migration bridge. \\[3pt]
\pkg{langchain-<provider>} & One per model vendor. Chosen per project. \\[3pt]
\pkg{langgraph-checkpoint-<backend>} & Postgres, SQLite, Redis. Chosen per
  project. \\[3pt]
\pkg{langsmith} & Tracing and evaluation. \\[3pt]
\pkg{langchain-mcp-adapters} & Tools from MCP servers
  (Ch.~\ref{ch:ecosystem}). \\[3pt]
\pkg{deepagents} & Planning and subagents over LangGraph. Pre-1.0. \\
\bottomrule
\end{tabularx}
\end{center}

\begin{warning}
\textbf{These are separate version lines.} At the versions this book pins,
\pkg{langgraph} is 1.2.x while \pkg{langgraph-checkpoint} is 4.x,
\pkg{langgraph-prebuilt} is 1.1.x and \pkg{langgraph-sdk} is 0.4.x. ``We are on
LangGraph 1.2'' is not a complete description of an environment. Pin the lot, in
a committed lockfile.
\end{warning}

\code{langchain.retrievers} & Retrieval as a tool (Ch.~\ref{ch:tools}) & \\[3pt]

  removed.} Still imports and works \\
\bottomrule
\end{tabularx}
\end{center}

\begin{warning}
The error you get is \code{ModuleNotFoundError: No module named
'langchain.chains'} --- the ordinary Python error for a typo. It does not mention
\pkg{langchain-classic}, 1.0, or that the code was ever correct. Most of the
first hour of a migration is spent discovering by search what one line of error
text could have said.
\end{warning}

\section{Migrating, in order}
\label{sec:appA-migration}
\index{migration!order of work}
\index{migration!checklist}

\begin{enumerate}[leftmargin=1.4em]
\item \textbf{Build the evaluation set first.} Before changing anything. Without
      it you cannot distinguish a regression from a difference, and every later
      step is guesswork. Chapter~\ref{ch:observability}.
\item \textbf{Inventory.} Grep for the retired names: \api{AgentExecutor},
      \api{initialize\_agent} and \api{LLMChain}, plus imports from the
      \code{chains}, \code{memory}, \code{retrievers} and \code{hub}
      modules.
\item \textbf{Install \pkg{langchain-classic} and rewrite imports.} The project
      runs again, unchanged in behaviour. Stop here and commit.
\item \textbf{Agents.} \api{AgentExecutor} $\rightarrow$ \api{create\_agent}.
      Custom callbacks and wrappers usually become middleware
      (Ch.~\ref{ch:agents}).
\item \textbf{Memory.} Memory classes $\rightarrow$ a checkpointer with a
      \code{thread\_id}. This is a design change, not a substitution: read
      Chapter~\ref{ch:persistence} before starting.
\item \textbf{Retrieval.} A fixed retrieval step $\rightarrow$ a tool the agent
      may call. Chapter~\ref{ch:context} measured why this matters for cost.
\item \textbf{Response parsing.} If you have a module that branches per provider,
      \api{content\_blocks} deleted the need for it
      (Ch.~\ref{ch:models}).
\item \textbf{Re-run the evaluation set} after each step, not at the end.
\end{enumerate}

\begin{note}
LCEL composition survives. If your 0.x code pipes \api{Runnable}s together, that
part still works and does not need touching.
\end{note}
